  • A 新增 By time / Search / Filter 工具条和 Finished → Live → Upcoming 状态组；Live 默认展开。
  • 所有新增 Live 卡使用统一中性样式，不继承 Recommended 的强化样式；比赛行点击后进入独立比赛内页。

取数

  • 新增 Live 数据：live_count、status、clock、competition_logo_url、home_crest_url、away_crest_url。
  • 新增入口排序字段：live_preview_sort_order；比赛详情跳转携带 match_id、来源和日期上下文。

  • A 状态组固定为 Finished → Live → Upcoming，默认展开状态为 false / true / false。
  • 去重仍使用 match_id + status_period，排序优先复用线上赛事排序和开赛时间。

交互

  • 点击比赛行直接进入独立比赛内页；点击关注按钮只更新关注状态。
  • Live 列表返回时恢复线上日期和来源上下文，公共顶部与底部区域不跳动。

边界处理

  • 非 Today 或 Live 数量为 0 时隐藏 B 的新增入口；A 直达 Live 显示线上约定的空态。
  • 缺少比分、赛徽或队徽时使用线上占位规则，不改变新增卡片和比赛行高度。
  • 推送延迟、接口失败和重试继续沿用线上策略。

比赛详情与关注

新增独立比赛内页与后续入口

精选比赛内页点击比赛行后跳转

展示位置

  • 从 Recommended 比赛列表、赛事展开列表或 Live 状态列表点击比赛后，在当前浏览器标签页打开独立比赛内页。
  • 比赛内页覆盖原列表内容，使用独立 URL；浏览器返回或页面返回入口回到原日期和来源列表。

展示内容

  • 展示联赛名与真实赛徽、双方真实队徽与队名、比分或开赛时间、比赛状态、摘要/时间线/统计页签和关注按钮。
  • 从不同来源进入时保留 from、日期和比赛状态上下文；不在列表页展示底部详情窗口。

取数

  • 详情字段：match_id、competition_name、home_team、away_team、score、status、kickoff_time、featured_reason。
  • 关注字段：is_following、notification_permission、updated_at。

计算

  • Upcoming 显示开赛时间；Live 与 Finished 显示比分；状态文案统一由 status 映射。
  • 关注按钮采用服务端最终状态；同一 match_id 在所有入口实时同步。

交互

  • 点击比赛行直接进入独立比赛内页；不打开底部弹层、遮罩或二次确认窗口。
  • 点击页面返回入口或使用浏览器返回回到原日期和来源列表；直接打开 URL 时使用默认比赛状态。
  • 关注按钮采用乐观更新，接口失败时回滚并提示；不因关注操作自动进入详情。

边界处理

  • 比赛参数缺失时按状态显示安全默认值；缺少队徽时保留固定尺寸占位，不能改变比分区高度。
  • 比赛取消或延期时主状态替换比分区域，并保留双方和比赛中心入口。
  • 无通知权限时允许保存关注，随后单独引导授权；拒绝授权不取消关注。

比赛列表优化 A/B 测试

新增 A/B 方案与效果测量

方案 B · 横滑直播预览打开方案 A Live

展示位置

  • 实验入口为 Match 页面中的 All + Today；Recommended 页签和非当天日期不参与本实验。原型顶部提供 A/B 方案切换页签，对照组使用 ?variant=control 打开三页签版本。
  • 实验配置、分流和埋点在客户端启动时完成，用户在整个实验周期内保持同一方案。

展示内容

  • 当前文档：B 测试，在 All 页面展示横滑 Live 预览，左右两端提供 Finished / Upcoming 入口。
  • A 对照组：顶部展示 All / Recommended / Live 三个页签；点击 Live 保持当前 URL、状态栏、三页签、日期栏和底部导航不变，只把主内容切换为 By time / Search / Filter、Finished / Live / Upcoming 与赛事比赛行；All 页面不展示横滑 Live 预览。
  • B 实验组：Live now 标题行、场次数、View all，以及在赛事名左侧展示真实赛徽、同时展示分钟、双方队徽、球队和比分的横滑卡；最左为 Finished、最右为 Upcoming 入口。
  • 两组使用同一批比赛数据、日期范围、状态口径和详情页，只有 Live 入口呈现方式不同。

取数

  • 分流字段：experiment_id、variant、user_id 或稳定设备 ID、assignment_time。
  • 行为事件：live_preview_exposure、live_card_impression、live_card_click、live_view_all_click、live_status_entry_click、match_detail_open。
  • 事件属性统一携带 match_id、status、position、live_count、selected_date、device_width。

计算

  • 主要指标 = 直播模块曝光用户中，点击任一 Live 入口、Live 卡或进入比赛详情的用户数 ÷ 直播模块曝光用户数。
  • 次要指标：Live 卡点击率、View all 点击率、Finished/Upcoming 入口使用率、首次打开比赛详情耗时 P50、单次会话打开的比赛详情数。
  • 按用户去重；同一用户同一自然日只计一次曝光和一次主要转化，避免重复刷新放大结果。

交互

  • 采用 50/50 随机分流，按用户或稳定设备 ID 固定，实验期间不因登录、刷新或日期切换改变方案。
  • 正式实验前运行 7 天基线，使用基线主要指标估算样本量；正式实验至少覆盖 14 天和两个完整周末。
  • 实验监控按天查看曝光、主要指标和护栏指标；不得在看到中期领先后提前结束。
  • 判定规则：B 组主要指标相对提升至少 5% 且 95% 置信区间不跨 0；护栏无显著恶化，则推荐全量发布。

边界处理

  • 仅统计成功渲染 Live 模块且 Live 数量大于 0 的用户；无直播、接口失败、机器人、内部账号和重复设备剔除。
  • 护栏指标包括比赛详情总打开率、页面退出率、Matches 首屏加载耗时和客户端错误率；任一恶化超过 3% 或错误率超过基线 0.2 个百分点，暂停发布并排查。
  • 样本不足、分流失衡超过 5%、埋点缺失超过 2% 或置信区间跨 0 时，结论标记为“无法判断”，延长一周，不得宣布 B 胜出。
  • 实验结束后保留 experiment_id、方案、日期、Live 场次数和位置属性，支持按市场、设备宽度和比赛日复盘。
