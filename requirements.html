01

页面导航与日期

比赛页面模式切换、日期选择与滚动同步

精选 · 今天直接操作比赛原型

展示位置

  • 位于 Demo 外层、手机画布上方展示 A/B 方案切换页签；手机画布内部的设备状态栏下方展示 All / Picks，A 对照组额外展示独立 Live 页签。
  • 日期栏始终位于比赛内容之前，不随比赛列表横向滚动。

展示内容

  • B 实验组只保留两个入口：All 承载完整比赛目录；Picks 展示系统精选的重要比赛，包含重点联赛与用户关注比赛。A 对照组额外展示独立 Live 页签。
  • 日期栏固定展示 5 天：前 1 天、当天、后 3 天；每项包含星期与日号。
  • All 与 Picks 共用同一日期栏高度（移动端固定为 50px），切换页签时不产生垂直跳动。
  • 当前页签使用红色底线，当前日期使用浅红底与红色文字。

取数

  • 客户端状态：current_view、selected_date、user_timezone。
  • 日期按用户时区生成；比赛请求统一携带 selected_date 和 timezone。

计算

  • 日期窗口 = [当地今天 - 1 天, 当地今天 + 3 天]。
  • 仅当日期等于用户当地自然日时显示 Today，其他日期显示本地化星期缩写。

交互

  • 切换页签时保留 selected_date，并将新页面滚动到该日期对应内容。
  • Picks 中点击日期，平滑滚动到对应日期分区；手动纵向滚动跨入新日期时，日期栏同步更新。
  • Matches 中点击日期，重新请求并渲染该日期的 Live、Top Competitions 与 All Competitions 数据。

边界处理

  • 日期无比赛时显示空态，不回退到其他日期数据，也不隐藏该日期。
  • 用户时区发生变化后，以新时区重新计算 Today；已打开的比赛详情不强制关闭。
  • 日期接口失败时保留上一次成功数据，并展示非阻断重试入口。
02

直播入口与状态列表

全部比赛顶部直播入口与赛前、赛中、赛后状态列表

直播预览与状态列表横滑比赛，点击查看全部

展示位置

  • Live 入口仅在 Matches + Today 展示，紧贴日期栏，位于所有赛事目录之前。
  • Matches 不展示 You may like 推荐卡模块；Live 横滑预览是日期栏后的第一个内容模块。
  • B 实验组点击 View all 后在新标签页打开独立 Live 列表页面，原 Matches 页面保持不变；不新增顶部 Live 页签，Live 页面仍保持 Matches 页签选中。A 对照组直接从顶部 Live 页签进入。

展示内容

  • 模块标题行展示红色直播点、Live now、Live 场次数与 View all；下方横滑卡在赛事名左侧展示固定尺寸的真实赛徽，并展示比赛分钟、双方队徽、队名与实时比分。
  • 首屏至少完整展示 1 张卡并露出下一张卡，明确横滑方向；卡片固定高度，赛事名和队名超长时单行省略。
  • 横滑串最左端展示 Finished 入口，最右端展示 Upcoming 入口；初始位置停在第一张 Live 比赛卡。
  • 横滑预览内所有 Live 卡使用统一白底与中性边框，不因 is_featured 增加底色或强调边线。
  • 二级列表顶部展示返回按钮、Live matches 标题、Live 场次数，以及 By time / Search / Filter 工具条。
  • 状态组顺序固定为 Finished → Live → Upcoming；Live 默认展开，另外两组默认收起。
  • 展开状态组后按赛事分组；赛事头展示真实赛徽、赛事名和组内场次数，比赛行展示状态时间、双方队徽、队名、比分与关注按钮。
  • Live 标题、比赛分钟与比分使用红色；重要比赛可增加红色左边线和浅红背景，普通比赛不增加该高亮。

取数

  • 比赛字段：match_id、competition_id、competition_name、competition_logo_url、status、clock、kickoff_time、score。
  • 球队字段：home_team、away_team、home_crest_url、away_crest_url；用户字段：is_following。
  • 高亮字段：is_featured；预览排序字段：live_preview_sort_order；Live 更新优先使用推送，连接失败后每 15 秒轮询一次。

计算

  • 状态组数量 = selected_date 与 status 匹配的唯一 match_id 数量；标题数量与横滑卡数量均取 Live 组结果。
  • 横滑卡优先按 live_preview_sort_order 升序；字段缺失时按赛事排序和开赛时间回退。
  • 横滑内容顺序固定为 Finished 入口 → Live 比赛卡 → Upcoming 入口；初始偏移量等于 Finished 入口宽度加卡片间距。
  • 比赛先按状态组归类，再按 competition_sort_order、赛事名排序；赛事内默认按开赛时间升序。
  • 计时显示优先级：中场显示 HT，常规进行中显示分钟，补时与加时使用数据源标准值。
  • 同一 match_id + status_period 仅保留更新时间最新的一条，避免推送重发造成重复比赛。

交互

  • 左右滑动浏览 Live 卡片；点击卡片打开 Match Detail，点击标题行的 View all 在新标签页打开独立 Live 列表页面。
  • 点击 Finished 或 Upcoming 入口跳转至独立 Live 列表页面，并默认展开所选状态组；顶部 Matches 保持选中。
  • 点击返回按钮或顶部 Matches 回到赛事目录，并恢复原日期上下文。
  • 点击 Finished、Live、Upcoming 标题独立展开或收起，可同时展开多个状态组。
  • By time 切换为跨赛事时间排序；Search 搜索球队或赛事；Filter 打开状态、赛事和关注筛选。
  • 点击比赛行打开 Match Detail；点击关注按钮只更新关注状态，不触发比赛详情。

边界处理

  • 非 Today 或 Live 数量为 0 时隐藏完整横滑模块，不保留空白占位；通过旧链接进入时显示无直播空态并提供返回。
  • 比分缺失但状态为 LIVE 时显示短横线，并继续展示双方、比赛时间和赛事信息。
  • 赛徽或队徽加载失败时使用固定尺寸中性占位，不改变行高；赛事名和队名超长时单行省略。
  • 推送超过 30 秒未更新时标记数据延迟；接口失败保留最近一次成功列表并提供重试。
03

热门联赛

热门联赛目录、重点球队提示与完整比赛展开

冠军联赛 · 展开重点比赛有独立氛围

展示位置

  • 位于 Live 横滑预览下方；非 Today 没有 Live 模块时，直接承接日期栏。
  • 每个联赛使用独立折叠行，默认收起，展开内容紧跟该联赛行。

展示内容

  • 联赛行高度为 52px，展示赛徽缩写、联赛名、最多 2 枚重点球队队徽、当日比赛数和展开箭头。
  • 正在比赛的重点球队队徽使用红色描边，并在每枚队徽右上方空白区展示动态三柱直播波形；全页最多突出 3 支。
  • 已结束比赛的重点球队使用低饱和队徽、灰色描边，并在每枚队徽右上方空白区展示 FT 状态牌；全页最多突出 2 支。
  • 展开后展示该联赛当前日期下的全部比赛，不是只展示热门比赛。
  • 比赛行展示日期、时间、双方队徽与队名；精选比赛增加红色左边线和浅红背景，不使用额外小图标。

取数

  • 联赛字段：competition_id、name、mark、brand_color、sort_order。
  • 日期聚合：match_count、matches[]、featured_team_ids[]、featured_team_rank、featured_team_status。
  • 比赛字段与 Live 模块共用；精选状态使用统一 is_featured。

计算

  • match_count = 当前日期、当前联赛下可展示的唯一 match_id 数量。
  • 重点队徽由服务端按 featured_team_rank 降序返回，客户端最多取 2 个；超过 2 个不显示 +N。
  • 队徽状态优先级为 Live > Finished > Upcoming；同一球队只展示一个状态。
  • 全页直播高亮最多 3 个、已结束高亮最多 2 个；达到上限后，其余队徽恢复普通样式。
  • 联赛排序使用运营配置 sort_order，相同值按当日比赛数降序。

交互

  • 点击整行展开或收起，箭头同步旋转；允许多个联赛同时展开。
  • 点击展开后的比赛行进入 Match Detail；滚动位置保留在当前联赛上下文。

边界处理

  • 无重点球队时移除队徽轨道，联赛名称获得剩余空间。
  • 超长联赛名称单行省略，队徽、比赛数和箭头固定保留；比赛数超过 99 显示 99+。
  • 队徽加载失败时显示联赛色中性的球队首字母占位，不改变行高。
  • 展开请求失败时保持联赛行展开，并在内容区显示重试状态。

全部联赛

国家与联赛的长尾比赛目录

全部联赛 · 国家展开不显示按国家说明

展示位置

  • 位于 Top Competitions 全部联赛之后，同属 Matches 的连续纵向列表。
  • 标题仅显示 All Competitions，不展示 By country 副文案。

展示内容

  • 国家行展示国家缩写标记、国家名称、当前日期比赛总数和展开箭头。
  • 展开后展示该国家有比赛的全部联赛；联赛子行展示赛徽缩写、联赛名和比赛数。
  • 国家行保持紧凑，列表可连续展示大量国家，不使用横向卡片。

取数

  • 国家字段：country_id、country_name、country_code、market_priority。
  • 联赛字段：competition_id、name、mark、match_count。

计算

  • 国家比赛数 = 该国家所有联赛在 selected_date 下可展示比赛数之和。
  • 国家排序先按 market_priority，再按比赛数降序；无配置项按本地化国家名排序。
  • 国家展开后只显示 match_count > 0 的联赛。

交互

  • 点击国家整行独立展开或收起；允许多个国家同时展开。
  • 切换日期后保留已经展开的国家 ID，但重新计算并更新联赛与场次数。

边界处理

  • 国家当日比赛数为 0 时不进入列表；整个长尾目录为空时隐藏 All Competitions 标题。
  • 国家下联赛超过 30 个时分批渲染，滚动到底继续加载，避免一次创建过多节点。
  • 国家或联赛缺少品牌色时使用统一中性深灰，不随机生成颜色。

精选比赛列表

少量重要比赛的连续日期列表与选赛逻辑

精选 · 连续日期日期随滚动同步

展示位置

  • 位于 Match 模块的 Picks 页签内；多个日期的比赛上下连续展示，不通过下拉筛选切断列表。
  • 日期分隔条下按联赛分组，联赛头与其比赛保持相邻。

展示内容

  • 日期分区展示日期；联赛头展示赛徽、联赛名、该组场次数和折叠箭头。
  • 比赛行展示时间或赛中分钟、双方队徽、队名、比分和关注按钮。
  • 时间列只显示 FT / HT / 分钟 / 开赛时间，不重复显示 Finished、Live、Upcoming 文案。
  • 列表中不展示 Featured Clash、推荐原因等解释标签；重要性通过进入 Picks 列表本身表达。

取数

  • 比赛字段：match_id、selected_date、competition、teams、status、clock、score。
  • 选赛字段：importance_score、competition_tier、stage_weight、team_popularity、rivalry_weight、attention_weight、manual_include、manual_exclude。

计算

  • importance_score = 联赛级别 0–30 + 赛制/争冠阶段 0–25 + 双方球队热度 0–25 + 德比/宿敌 0–10 + 全局关注度 0–10。
  • manual_exclude 优先级最高；manual_include 强制进入；其余比赛需 importance_score ≥ 65。
  • 单日最多展示 8 场，超过后按分数、开赛时间、match_id 稳定排序；不足时不使用低分比赛补位。
  • 日期升序；日期内联赛按该组最高分降序；联赛内按 Live、Upcoming、Finished 排序。

交互

  • 点击日期跳转对应分区；纵向滚动跨日期后，顶部日期栏自动切换。
  • 点击联赛头收起或展开该组；点击比赛行打开 Match Detail。
  • 点击星标只更新 Following 状态，不触发比赛详情；成功后显示轻量反馈。

边界处理

  • 单日没有符合阈值的比赛时显示“当天暂无 Picks 比赛”，不降低阈值补满数量。
  • 比分、队徽或队名任一侧缺失时按完整比赛行降级，不把缺失值显示成 0。
  • 编辑强制选赛与自动规则冲突时记录最终来源，便于回溯和 A/B 分析。

比赛详情与关注

比赛详情底部弹层、关注状态与后续入口

精选比赛详情从下至上打开

展示位置

  • 从 Picks 比赛列表、赛事展开列表或 Live 状态列表点击比赛后，从页面底部向上弹出。
  • 弹层覆盖当前 Match 页面，但保留背景上下文与遮罩。

展示内容

  • 展示联赛名、双方队徽与队名、比分或开赛时间、比赛状态和 Open Match Centre 主按钮。
  • 从 Picks 进入时可展示服务端提供的精选原因；从 Live 进入时展示实时跟进提示，不重复解释重要性。

取数

  • 详情字段：match_id、competition_name、home_team、away_team、score、status、kickoff_time、featured_reason。
  • 关注字段：is_following、notification_permission、updated_at。

计算

  • Upcoming 显示开赛时间；Live 与 Finished 显示比分；状态文案统一由 status 映射。
  • 关注按钮采用服务端最终状态；同一 match_id 在所有入口实时同步。

交互

  • 支持关闭按钮、背景点击、Escape 和系统返回；关闭后恢复触发入口焦点与列表滚动位置。
  • Open Match Centre 进入完整比赛中心；返回后回到原日期和原列表位置。
  • 关注按钮采用乐观更新，接口失败时回滚并提示；不因关注操作自动进入详情。

边界处理

  • featured_reason 缺失时隐藏原因模块，不展示通用占位解释。
  • 比赛取消或延期时主状态替换比分区域，并保留双方和比赛中心入口。
  • 无通知权限时允许保存关注，随后单独引导授权；拒绝授权不取消关注。

比赛列表优化 A/B 测试

验证直播预览改版是否提升发现、点击与连续浏览效率

方案 B · 横滑直播预览打开方案 A

展示位置

  • 实验入口为 Match 页面中的 All + Today；Picks 页签和非当天日期不参与本实验。原型顶部提供 A/B 方案切换页签，对照组使用 ?variant=control 打开三页签版本。
  • 实验配置、分流和埋点在客户端启动时完成，用户在整个实验周期内保持同一方案。

展示内容

  • A 对照组：顶部展示 All / Picks / Live 三个页签，Live 直接打开独立 Live 列表页面；All 页面不展示横滑 Live 预览。
  • B 实验组：Live now 标题行、场次数、View all，以及在赛事名左侧展示真实赛徽、同时展示分钟、双方队徽、球队和比分的横滑卡；最左为 Finished、最右为 Upcoming 入口。
  • 两组使用同一批比赛数据、日期范围、状态口径和详情页，只有 Live 入口呈现方式不同。

取数

  • 分流字段：experiment_id、variant、user_id 或稳定设备 ID、assignment_time。
  • 行为事件：live_preview_exposure、live_card_impression、live_card_click、live_view_all_click、live_status_entry_click、match_detail_open。
  • 事件属性统一携带 match_id、status、position、live_count、selected_date、device_width。

计算

  • 主要指标 = 直播模块曝光用户中，点击任一 Live 入口、Live 卡或进入比赛详情的用户数 ÷ 直播模块曝光用户数。
  • 次要指标：Live 卡点击率、View all 点击率、Finished/Upcoming 入口使用率、首次打开比赛详情耗时 P50、单次会话打开的比赛详情数。
  • 按用户去重；同一用户同一自然日只计一次曝光和一次主要转化，避免重复刷新放大结果。

交互

  • 采用 50/50 随机分流，按用户或稳定设备 ID 固定，实验期间不因登录、刷新或日期切换改变方案。
  • 正式实验前运行 7 天基线，使用基线主要指标估算样本量；正式实验至少覆盖 14 天和两个完整周末。
  • 实验监控按天查看曝光、主要指标和护栏指标；不得在看到中期领先后提前结束。
  • 判定规则：B 组主要指标相对提升至少 5% 且 95% 置信区间不跨 0；护栏无显著恶化，则推荐全量发布。

边界处理

  • 仅统计成功渲染 Live 模块且 Live 数量大于 0 的用户；无直播、接口失败、机器人、内部账号和重复设备剔除。
  • 护栏指标包括比赛详情总打开率、页面退出率、Matches 首屏加载耗时和客户端错误率；任一恶化超过 3% 或错误率超过基线 0.2 个百分点，暂停发布并排查。
  • 样本不足、分流失衡超过 5%、埋点缺失超过 2% 或置信区间跨 0 时，结论标记为“无法判断”，延长一周，不得宣布 B 胜出。
  • 实验结束后保留 experiment_id、方案、日期、Live 场次数和位置属性，支持按市场、设备宽度和比赛日复盘。
